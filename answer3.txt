三条会影响设计的事实：

  1) max_distance 全是 5000 → 飞行路程完全不构成约束，不用做这一列。

  2) 【寿命是唯一的射程约束，而且卡得很死】
     总寿命 = (弹 baseLifetime + 材料 addedLifetime) tick
     9 个 json 都没写 baseLifetime → 全部走 fallback 20 tick
     材料 addedLifetime 跨度 5 ~ 140 → 实际寿命 25 ~ 160 tick
     而 APHE 打到弹道最大射程 515 格要 153.8 tick
     → 单管钢(+50 → 70t) 只到 ~343 格；宽单管钢(+85 → 105t) 能到 ~457 格
     不同材料的可达射程差一倍以上。这就是这张对比表最大的价值。

  3) 高爆/防空/燃烧弹 质量 0.1、动量封顶 10 → 等效动量恒为 0.2~2.6，这一列对它们
     没有意义。所以弹道列显示什么也要按弹种可配。

三、属性分层
================================================================================

做成【类型级别】区分，不用布尔标记 —— 不随材料变的属性在编译期就读不到材料字段。

3.1 两个上下文

  /** 只有炮弹。区块 A、B 用它。 */
  record DualCannonShellContext(Entry entry, DualCannonMunitionProperties shell)

  /** 炮弹 + 一种炮管材料。区块 C 每一行用它。 */
  record DualCannonLoadout(
      DualCannonShellContext shell,
      DualCannonMaterial material,
      DualCannonMaterialProperties barrel,
      float commandModifier,      // 预留，默认 1
      float equipmentModifier     // 预留，默认 1
  ) {
      double durabilityModifier();  // barrel.durabilityMassModifier() * command * equipment
      double effectiveMass();       // 基础质量 * durabilityModifier()
      int    lifetimeTicks();       // 弹 baseLifetime + 材料 addedLifetime，再乘修正
      double explosionPower();      // 基础爆炸 * DualCannonModifiers.explosionPower(kind, mod)
      double fireChance();          // 燃烧弹：基础 * DualCannonModifiers.incendiaryFire(mod)
      double fireRange();           // 燃烧弹：基础 * DualCannonModifiers.incendiaryRange(mod)
      double reloadCoefficient();   // 弹 reloadTimeCoefficient * barrel.reloadTimeModifier()
  }

  注意 lifetimeTicks 是【相加后】的最终值 —— baseLifetime 只是基础，
  必须加上炮管的 addedLifetime，界面显示的就是这个和。

3.2 StatSpec（一套泛型两种用法）

  record StatSpec<C>(String key, ToDoubleFunction<C> value, StatFormat format, int priority)
  interface StatSink<C> { void add(StatSpec<C> spec); void addIf(boolean c, StatSpec<C> s); }
  StatFormat: PLAIN2 / PERCENT / M_PER_SEC / SECONDS / DEGREES / TICKS
  value 返回 NaN = 本弹种不适用，UI 跳过。

3.3 物品上的收集口

  在 FuzedDualCannonProjectileBlockItem 上：

  /** 区块 A：不随材料变化。 */
  public void collectShellStats(StatSink<DualCannonShellContext> sink) {
      sink.add(DualCannonStats.MUZZLE_VELOCITY);
      sink.add(DualCannonStats.DRAG);
      sink.add(DualCannonStats.GRAVITY);
      sink.add(DualCannonStats.BASE_MASS);
      sink.add(DualCannonStats.DEFLECTION_ANGLE);
      sink.add(DualCannonStats.MAX_MOMENTUM);
      sink.add(DualCannonStats.SMASH_TOUGHNESS);
      sink.add(DualCannonStats.MAX_RANGE);
  }

  /** 区块 C 的前几列：随材料变化。只留爆炸、寿命、装填、点火。 */
  public void collectMaterialStats(StatSink<DualCannonLoadout> sink) {
      sink.add(DualCannonStats.LIFETIME);   // priority 100，决定可达射程，永远不能砍
      sink.add(DualCannonStats.RELOAD);     // priority 80
  }

  子类：
    HE / APHE / APBC / SAP / 防空       super + add(EXPLOSION_POWER)   priority 90
    燃烧 HE                             super + add(EXPLOSION_POWER)
                                              + add(FIRE_CHANCE) + add(FIRE_RANGE)  priority 85
    AP Shot / 延伸 AP（惰性）            只调 super（Kind.AP_SHOT 的爆炸倍率恒为 0）

  → M（材料列数）= 2（AP弹） / 3（大部分） / 5（燃烧弹）

  防空弹的高度加成不随材料变，放 collectShellStats，别放错块。

3.4 弹道列显示什么，也按弹种可配

  public List<BallisticColumnMode> ballisticModes() {
      return List.of(BallisticColumnMode.MOMENTUM, BallisticColumnMode.FLIGHT_TIME);
  }
  高爆/防空/燃烧覆写成 List.of(FLIGHT_TIME, IMPACT_SPEED)，把没意义的动量换掉。

  enum BallisticColumnMode { MOMENTUM, FLIGHT_TIME, IMPACT_SPEED }

  切换按钮在这个列表里轮换。注意 FLIGHT_TIME / IMPACT_SPEED 与材料无关，
  切过去后每行数值相同 —— 建议此时把区块 C 的弹道列折叠掉，只看区块 B 那两行。

3.5 动量公式扩展点

  public DualCannonMomentumModel momentumModel() { return DualCannonMomentumModel.CAPPED; }
  CAPPED = (loadout, speed) ->
      DualCannonPenetrationModel.getCappedMomentum(loadout.shell().shell(), speed, loadout.effectiveMass())

  你说 getCappedMomentum 还没做完、之后要让 resolve() 也调它来统一公式。
  这里只经过物品这一层，等你把 resolve() 接过去之后，表格和实战自动就是同一个公式。


================================================================================
四、列预算
================================================================================

  TOTAL_COLUMNS      可配，默认 13（UI 给 11/13/15 的下拉）
  1                  材料名
  M                  collectMaterialStats 的列数（2 / 3 / 5）
  B = TOTAL - 1 - M  弹道列数

  APHE：M=3（寿命/装填/爆炸）→ B = 13-1-3 = 9
  燃烧弹：M=5 → B = 7
  AP 弹：M=2 → B = 10

  保底：B < 4 时按 priority 从低到高把材料列折进「悬停材料名看全部」的 tooltip，
  仍不够就把 TOTAL 抬到 1+M+4 并提示。

  弹道列距离取法：等分该弹的弹道最大射程，d_i = maxRange * i / B。
  区块 B 和区块 C 共用同一套距离，所以列能严格对齐。

  MaterialRow             compute(loadout, skeleton, specs, missingSingleVariant)
                          只算两样新东西：动量列 + 可达标记，其余都从骨架来。
                          formatBallistic() 在打不到的格子上直接印 "-"。
                          lastReachableColumn() 给界面画「该材料到此为止」。
  DualCannonTable         炮弹属性 / 材料列 / 骨架 / 可选模式 / 材料列表，
                          外加 nextMode() 给切换按钮轮换。
  DualCannonTableSource   两级惰性 + 会话级缓存：
                            shells()  只列方块，不解析任何属性
                            table()   选中才算，一发弹一次
                            row()     一行一算，页面要哪行算哪行
                          列预算 = 总列数 - 1(材料名) - 材料列数，
                          材料列先按 priority 砍到给弹道留够 MIN_BALLISTIC_COLUMNS(4)。
                          invalidate() 供 /reload 后清空。

9.6 第 5 步：分页

  utils/Paginator.java  纯逻辑，不依赖任何 Minecraft 类型
    setSource / setFilter / setComparator / setPageSize
    page / pageIndex / pageCount / totalCount / pageSize / isEmpty / absoluteIndex
    next / prev / first / last / goTo / revealItem

    几个刻意的行为：
      · pageCount 至少为 1，空表也有第 0 页，界面不用特判
      · goTo 越界不报错，直接夹紧
      · setPageSize 按【当前页首行的绝对下标】重新定位，窗口缩放时内容不会乱跳
      · setFilter / setComparator 之后页码自动夹回有效范围
      · page() 回传只读视图；setSource 会复制，不持有调用方的 list

9.7 第 6 步：界面

  client/gui/PageControls.java
    左右按钮 + 中间「3 / 12」。自己不是 Widget，而是把两个 Button 交给屏幕注册，
    所以任何列表界面都能复用，不用继承某个布局。
    到头 / 到尾时自动把对应按钮置灰。

  client/gui/DualCannonCodexScreen.java   第 1 屏
    列出 9 种弹（图标 + 名字），鼠标悬停高亮，点击进对比表。
    顶部两个循环按钮：炮管过滤（仅单管 / 单管+补漏 / 全部）、列数（11 / 13 / 15）。
    这两个设置在这里选，进对比表后沿用；改动会重建 DualCannonTableSource，
    因为两者都会改变表的形状。
    列出弹种时不解析任何属性 —— 惰性是从这里开始的。

  client/gui/DualCannonCompareScreen.java 第 2 屏
    三块自上而下：
      A  炮弹自身属性，两列排布，走 table.applicableShellStats()
      B  弹道骨架：距离 / 落弹时间 / 存速，与下方弹道列严格对齐
      C  材料对比行，走 Paginator + source.rows()
    右上角切换按钮走 table.nextMode(current)；
    打不到的格子印 "-" 并变灰；补漏材料名前面加 * 并换色。
    窗口宽高按实际列数和行数算，不是写死的。

  client/gui/CBCMSFiringTableKeybind.java  入口
    按键默认【不绑定】（InputConstants.UNKNOWN），由玩家自己绑。
    没有默认绑定就不会和玩家已有的键冲突，而且射表是查阅用的，不是战斗中要按的。
    选按键而不是手册物品的原因：零资源 —— 不用模型、贴图、配方。
    等你要做手册物品时，把 ScreenOpener.open(new DualCannonCodexScreen()) 挪过去即可。
    注册挂在 CBCMSClientNeoForge.prepareClient（那里本来就有 modEventBus 和 forgeEventBus）。

  lang 两个文件各再追加 15 条：界面标题、过滤器名、列数、按键名等。
