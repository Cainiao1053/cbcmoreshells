L1  改公式：DualCannonPenetrationModel.resolve()
================================================================================

  下面这些是**写死在代码里**的，JSON 调不到，要改公式就改这里。
  行号是当前的，改动后会漂，按内容找更可靠。

  ── 动量计算（resolve，约 80–86 行）────────────────────────────────
      bonusMomentum = 1 + max(0, (speed − minVelocityForPenetrationBonus) × penetrationBonusScale)
      rawMomentum   = mass × bonusMomentum × speed
      momentum      = min(rawMomentum, maximumMomentum) × incidence
      durabilityPenalty = toughness / incidentVelocity
    想换成「动能制」就把 mass × speed 改成 0.5 × mass × speed²；
    想让入射角影响更陡就把 × incidence 改成 × incidence²。

  ── 穿透判定（resolve，约 88–92 行）────────────────────────────────
      momentum > toughness × 2.0                → 必穿
      momentum > toughness × 0.5                → 概率穿
          p = (momentum / toughness − 0.15) / 2.0
      其余                                       → 转跳弹/停止
    这里的 2.0 / 0.5 / 0.15 / 2.0 四个常数就是「穿深曲线」的形状，
    要调手感基本都是动这四个。想做成硬阈值就把概率段删掉。

  ── 强行破甲与上限门槛（resolve，约 94–96 行）──────────────────────
      canPenetrate = state.penetrations() < impact.maxPenetrations()
      forceSmash   = dualImpact.smashToughness() > toughness
      不可穿 / 不可破坏 / 判定失败 → tryBounce，失败再 stopOnBlock

  ── 穿透后的质量损耗与减速（penetrateBlock，约 105–143 行）──────────
      momentum > toughness × 3.0  → 扣 penalty × highPenetrationMassPenaltyScale
      momentum > toughness × 2.0  → 扣 penalty × penetrationMassPenaltyScale
      否则                        → 质量直接压到 0.1（写死的残余值）
      新速度 = 旧速度 × retainedAfterPenetration(旧质量, 新质量, impact)
    那个 3.0 / 2.0 的分档和 0.1 的地板都是写死的。

  ── 跳弹（tryBounce，约 145–174 行）────────────────────────────────
      条件：canBounce && ricochets < maxRicochets
            && deflection > 0 && incidence <= deflection
      概率：max(baseBounceChance, 1 − incidence / deflection)
      反射：v − n × (ELASTICITY × v·n)，再 × bounceVelocityRetained
      ELASTICITY = 1.7（文件顶部常量，第 33 行）
    ⚠ 注意这里是**取最大值**；旧的实体实现是「(1 − incidence/deflection) + baseChance」相加。
      要还原旧手感就把 max(...) 改成加法。

  ── 停止与崩落（stopOnBlock，约 176–188 行）────────────────────────
      质量清零 → 播停止特效 → 在命中点前方 2.0 格放一个崩落爆炸
      那个 2.0 的偏移距离是写死的。

  改完只要编译通过就生效，不需要动 shaolib，也不需要动注册。

L3  换掉整套判定模型
================================================================================

  接线点只有一处：DualCannonBehavior.tickServer()，约 95–101 行

      MunitionImpactSweep.sweep(context, start, end, sweepVelocity, properties,
          loadPolicy(projectile), this.entityHitOptions(context),
          clip 处理, this::applyImpactOutcome, this::applyEntityImpact,
          DualCannonPenetrationModel::resolve);   ← 把最后这个换掉

  最后一个参数就是 BlockImpactResolver，签名：
      MunitionImpactOutcome resolve(ProjectileServerContext<S>, ShaolibBlockHitResult,
                                    CbcLikeMunitionProperties)

  **写替代实现时必须自己负责的事**（最容易漏，漏了就是各种诡异 bug）：

    - 返回值必须是完整的 MunitionImpactOutcome，用这些工厂方法构造：
        MunitionImpactOutcome.penetrate(hit, nextPos, nextVel, destroyedBlock, shatter,
                                        impactVel, impactMass, destroyedBlockState)
        MunitionImpactOutcome.bounce(hit, nextPos, nextVel, impactVel, impactMass)
        MunitionImpactOutcome.stop(hit, shatter, impactVel, impactMass)
        MunitionImpactOutcome.uncertain(hit, impactVel, impactMass)
    - **UNCERTAIN 必须处理**：区块没加载时要返回 uncertain 让扫掠重试，
      不能当成命中，否则打未加载区域会凭空炸。
    - 破坏方块要走 BlockImpactSupport.tryDestroyImpactedBlock(context, hit)，
      它会respect保护/grief 规则；自己 setBlock 会绕过。
    - 质量扣减要自己 state.setDurabilityMass(...)，扣到 0 才会停下来。
    - 特效要自己调 CbcMunitionEffectPipeline.playPenetration / playBounce / playStop，
      不调就完全没有命中特效。
    - 穿透次数 / 跳弹次数不会自动加，是 DualCannonBehavior.applyImpactOutcome
      根据返回的 kinematics 去 increment 的 —— 所以 kinematics 要返回对。

  也就是说：resolver 不是「回答穿不穿」，而是「负责这一次命中的全部后果」。
  只想改判定逻辑的话，**别走 L3，改 L1 就够了**。

附 A：想让炮管材质 / 战斗指令 影响击穿公式
================================================================================

  每发炮弹可以携带一段 JSON 覆盖，发射时写入，解析器会叠加到数据包配置上。

    写入：CBCMSDualCannonShotOverrides.encode(...)
          → MountedDualCannonContraption.spawnRound 里 set 进
            CBCMSDualCannonData.DYNAMIC_PROPERTIES
    读取：CBCMSDualCannonProjectiles 注册时用的
          MunitionPropertyResolver.encodedJson(propertyType, DYNAMIC_PROPERTIES)

  现在只覆盖了 ballistics.durability_mass。想让指令/炮管也影响
  smash_toughness、maximum_momentum 之类，就在 encode() 里多加一段：

      overrides.add("dual_impact", 一个带你要覆盖字段的 JsonObject);

  格式就是数据包 JSON 的同一套结构，逐字段覆盖，没写的字段沿用配置值。

  ⚠ 另外有个已知的脆弱点，改这块时注意：
    耐久质量目前有两处 initializeDurabilityMass，
      AbstractFuzedShellBehavior.onSpawn      → 不带 durabilityModifier
      DualCannonPenetrationModel.resolve 第 49 行 → 带 durabilityModifier
    因为它只在「尚未设值」时写入，而 onSpawn 必定先跑，所以实际生效的是前者，
    数值是对的。但如果你改了流程、让质量在飞行中被清空重设，
    第 49 行就会再乘一次 modifier，变成 base × modifier²。
    要动这块的话，建议顺手把第 49 行的 × state.durabilityModifier() 去掉。

附 B：现成的备选模型 —— CBCMSLegacyPenetration
================================================================================

  同目录下 CBCMSLegacyPenetration.java 是从旧实体炮弹里保留下来的
  「面积采样式」击穿模型（技术储备，目前没接线）：

    averageToughnessBehind(level, pos, face)
        对命中面背后 3×3、深 3 层共 27 格取平均韧性
    penetrationToughness(mass) = mass² × 0.4 + mass × 1.2 − 1.5
    penetrates(...) = penetrationToughness > averageToughnessBehind

  与现用模型的区别：
    现用：动量制，看速度和入射角，薄板厚板拦阻能力接近
    备选：装甲厚度制，不看速度和角度，奖励间隔/复合装甲，口径主导

  接线方式：在 DualCannonPenetrationModel.resolve 里把
  第 88–92 行的判定换成调用 CBCMSLegacyPenetration.penetrates(...)，
  **其余部分（质量扣减、跳弹、特效、outcome 构造）全部保留** ——
  这是 L1 级改动，不用走 L3。

附 C：改完之后建议验一下
================================================================================

  1. 同一堵墙连续穿透，记录每层之后的速度与是否停下（验质量扣减与减速）
  2. 贴着大角度斜射装甲，看跳弹是否按预期触发（验 deflection 与概率公式）
  3. 打基岩/保护方块，确认不会被穿（现在会 respect 不可破坏，旧实现不会）
  4. 打未加载区块方向，确认不会凭空引爆（验 UNCERTAIN 分支）
  5. 多人环境下开一个客户端看数值是否一致（验 write/read 顺序没错位）
